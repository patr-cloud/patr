# runners/common/CLAUDE.md

The shared runner framework: the `RunnerExecutor` trait, `Runner<E>`, the actor tree, upstream WebSocket, local SQLite state and reconciliation. See `runners/CLAUDE.md` for the cross-cutting picture.

## Implementing an executor

- Implement `RunnerExecutor` (`src/executor.rs`). `initialize()` connects to the backend once and returns the executor itself, which is cloned into every actor and reconcile, so keep clones cheap (handles behind `Arc`).
- **The framework reconciles owners, not commands.** An `Owner` (`Deployment(id)`, `ManagedUrl(id)`, `System`) is the unit of work. For each owner the controller builds `expected(owner, &LocalState, &inputs)` (pure: an `ExpectedGraph` of objects and their dependencies, which never cross owners), reads `list(Some(owner))`, applies every object whose `patr.specHash` differs (dependencies first, a failed object blocks only its dependents), then deletes what's no longer expected (dependents first, skipping what's `in_use`).
- **The spec hash is the framework's.** It's `sha256(SPEC_VERSION ++ json(spec) ++ sorted (dependency id, dependency hash))`, so a changed dependency re-applies its dependents. Late-bound values (secret values, image names, config IDs) are resolved in `apply`, never in `expected`. Bump `SPEC_VERSION` when how objects are applied changes.
- **Ownership lives on the object**, as labels: `managed-by=patr`, `patr.owner`, `patr.specHash`. Objects without a valid `patr.owner` are ignored, never reaped. One runner per Docker host: a replacement runner takes over and reaps the previous one's objects.
- **Finalizers gate deletes.** An object `finalizers()` lists isn't deleted until each finalizer is done, and while its owner still expects anything, it isn't deleted at all (a volume whose path was removed keeps its data). Progress is persisted in `object_finalizer` (typed: `finalizer`, `state` and `last_error` are CHECKed enums, and `last_error` is a kind, never text), so a crash resumes it: `running` rows are reset to `pending` when the controller starts. Finalizers must be idempotent. The one kind today, `volume`, asks the API for the deployment (`GetDeploymentInfo`): a 401/404, or a 200 naming another runner, is done; a 200 naming this runner fails it, and a later reconcile retries.
- An `Err` from `apply` marks the owner failed: it's retried with backoff (1s → 5min) and its deployment reads `Errored`.
- Import surface is the prelude: `use common::prelude::*` (trait, `Runner`, `RunnerError`, config, `DatabaseType = sqlx::Sqlite`, `sqlx::{query, Row}`).

## Gotchas

- **Data access uses the compile-time-checked `query!` macro** (the prelude's, from `macros`), against SQLite. `sqlx.toml` points the macros at `RUNNER_DATABASE_URL` (the api's use `DATABASE_URL`) and maps the TEXT UUID/enum and `u16` INTEGER columns to their Rust types per table — **a new column of one of those kinds needs a line there**. The offline cache is `runners/common/.sqlx/`, regenerated by `just prepare` against `target/runner.db` (`just runner-db`).
- **Migrations and the schema DDL in `db/` use runtime `sqlx::query()`, never `query!`** — the schema is mid-change. Migrations self-register via `inventory`, take `(&mut DatabaseConnection, &RunnerSettings<()>)` (the `init_db` example passes a placeholder), and the DDL + bookkeeping insert must happen in **one transaction** (partial DDL leaves `*_new` temp tables that wedge retries).
- **Tests:** `cargo nextest run --package common`. `managed_mode::` tests are forced single-threaded (`.config/nextest.toml`) — they share one real HTTP test server on **fixed port 3000**. Non-managed tests get isolated temp SQLite and run in parallel.
- **FullResync diffs** (`src/actors/websocket.rs`): it fetches everything first, outside any transaction (`ListDeployment` filtered server-side by `runner`, `GetDeploymentInfo` per ID, managed URLs, secrets), then writes only the differences in one short transaction. Any failed call (429 and 5xx included) aborts it with SQLite untouched, so a failure never reads as "deleted". Runs on every WS (re)connect and on a timer. Write order matters: removed deployments (their managed URLs go with them) before upserts, and a deployment's probes are nulled before its `deployment_exposed_port` rows go (they FK each other both ways).
- **Intent and observed status are separate columns**, mirroring the API. `deployment.should_run` is the API's intent; `deployment.observed_status` (nullable) is written only by the runner. Upserts and resyncs set only the desired columns (`ON CONFLICT DO UPDATE SET` never names `observed_status`), and a delete takes it with the row. The runner sends a deployment's observed status upstream (`SendStatusUpdate`) whenever it changes, and every one of them after each resync, which catches the API up on whatever it missed while disconnected. The API drops the connection when it fails to store one, so the reconnect's resync sends it again. The runner never sends `Stopping` or `Unreachable`.
- **Migrations recreating `deployment` defer foreign keys** (`PRAGMA defer_foreign_keys = ON`, see `m007`): `PRAGMA foreign_keys = OFF` is a no-op inside the migration's transaction, and every child table references `deployment`. Copy it aside, drop it, recreate it under its own name, then re-insert — renaming a `*_new` table into place leaves the violations standing at commit.
- **Actors** (`src/actors/`): `RunnerSupervisor` spawns the `Controller` (the queue of owners: `pending`/`in_flight`/`dirty`, 4 at a time, `System` first, a full reconcile every 10 min), the `Observer` (status snapshots from `observe()` plus `watch()` hints, written to `deployment.observed_status`) and the `WebSocketActor`, and restarts whichever stops. They find each other by registered name (`ActorRef::where_is`), never by stored refs. A change to any non-`System` owner re-enqueues `System`, because the ingress mounts the other owners' routes.
- **A fresh database waits for the first resync.** `db::initialize` reports whether it created the database, and until the WebSocket actor's first resync sends `Start`, the controller reconciles nothing, or it would reap every object on the host. An existing database reconciles from its local state right away.
- `db::initialize` (migrations) runs **before** `E::initialize`. `run()` returns `!`: it awaits the actor tree, and exits non-zero if the tree stops without the exit signal, so systemd restarts it. rustls' crypto provider is installed manually in init because ring + aws-lc-rs are both linked.
