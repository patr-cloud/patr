# runners/common/CLAUDE.md

The shared runner framework: the `RunnerExecutor` trait, `Runner<E>`, the actor tree, upstream WebSocket, local SQLite state and reconciliation. See `runners/CLAUDE.md` for the cross-cutting picture.

## Implementing an executor

- Implement `RunnerExecutor` (`src/executor.rs`). Two-phase: `initialize()` builds heavy shared state once (Docker client, etc.) into `InitializedState`; **`new()` is called per reconcile pass and per actor spawn, so keep it cheap** (clone the handle).
- `list_running_*` **must return sorted streams** — reconciliation is a sorted merge of SQLite vs running actors.
- Returning `Err(RunnerError)` is the **retry signal**: on failure, an actor reports `Errored` upstream then returns `Err` to kill itself; the supervisor respawns with exponential backoff (1s → 5min).
- Import surface is the prelude: `use common::prelude::*` (trait, `Runner`, `RunnerError`, config, `DatabaseType = sqlx::Sqlite`, `sqlx::{query, Row}`).

## Gotchas

- **Data access uses the compile-time-checked `query!` macro** (the prelude's, from `macros`), against SQLite. `sqlx.toml` points the macros at `RUNNER_DATABASE_URL` (the api's use `DATABASE_URL`) and maps the TEXT UUID/enum and `u16` INTEGER columns to their Rust types per table — **a new column of one of those kinds needs a line there**. The offline cache is `runners/common/.sqlx/`, regenerated by `just prepare` against `target/runner.db` (`just runner-db`).
- **Migrations and the schema DDL in `db/` use runtime `sqlx::query()`, never `query!`** — the schema is mid-change. Migrations self-register via `inventory`, take `(&mut DatabaseConnection, &RunnerSettings<()>)` (the `init_db` example passes a placeholder), and the DDL + bookkeeping insert must happen in **one transaction** (partial DDL leaves `*_new` temp tables that wedge retries).
- **Tests:** `cargo nextest run --package common`. `managed_mode::` tests are forced single-threaded (`.config/nextest.toml`) — they share one real HTTP test server on **fixed port 3000**. Non-managed tests get isolated temp SQLite and run in parallel.
- **FullResync diffs** (`src/actors/websocket.rs`): it fetches everything first, outside any transaction (`ListDeployment` filtered server-side by `runner`, `GetDeploymentInfo` per ID, managed URLs, secrets), then writes only the differences in one short transaction. Any failed call (429 and 5xx included) aborts it with SQLite untouched, so a failure never reads as "deleted". Runs on every WS (re)connect and on a timer. Write order matters: removed deployments (their managed URLs go with them) before upserts, and a deployment's probes are nulled before its `deployment_exposed_port` rows go (they FK each other both ways).
- **Intent and observed status are separate columns**, mirroring the API. `deployment.should_run` is the API's intent; `deployment.observed_status` (nullable) is written only by the runner. Upserts and resyncs set only the desired columns (`ON CONFLICT DO UPDATE SET` never names `observed_status`), and a delete takes it with the row. The runner sends a deployment's observed status upstream (`SendStatusUpdate`) whenever it changes, and every one of them after each resync, which catches the API up on whatever it missed while disconnected. The API drops the connection when it fails to store one, so the reconnect's resync sends it again. The runner never sends `Stopping` or `Unreachable`.
- **Migrations recreating `deployment` defer foreign keys** (`PRAGMA defer_foreign_keys = ON`, see `m007`): `PRAGMA foreign_keys = OFF` is a no-op inside the migration's transaction, and every child table references `deployment`. Copy it aside, drop it, recreate it under its own name, then re-insert — renaming a `*_new` table into place leaves the violations standing at commit.
- `db::initialize` (migrations) runs **before** `E::initialize`. `run()` returns `!`. rustls' crypto provider is installed manually in init because ring + aws-lc-rs are both linked.
